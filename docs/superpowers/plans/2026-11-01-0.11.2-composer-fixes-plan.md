# 0.11.2 Prompt Composer Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task by task after explicit implementation approval. GitHub issues are the execution-status source of truth.

**Goal:** Address the seven composer fixes and enhancements requested after testing 0.11.1: #199, #200, #201, #202, #203, #204 and #205.

**Architecture:** Proposed: retain the embedded CodeMirror editor, shared live-session catalog and native Claude submission/queue. Decide shortcut ownership only after a supported-API and real-window feasibility check (#201, #202, #204, #205).

**Tech Stack:** Existing TypeScript, CodeMirror 6, CSS, Mocha/JSDOM and VS Code extension-host tests (package.json:L36-L48,L330-L360).

**Spec:** The seven issues are the durable requirements and per-item plans: #199–#205. The maintainer confirmed both invalid-reference flags and coloring (#201), and retaining both the reference browser and inline suggestions (#202). The original accepted session/queue/shortcut requirements remain in #145; implementation provenance is PR #198.

**Status:** Planning only; no runtime work authorized or started. Milestone: [0.11.2](https://github.com/glitchwerks/vscode-claude-workspaces/milestone/17). This is a new testing patch on the existing 0.11.x line, not a claim that 0.11.2 is published (#199–#205; docs/versioning-policy.md:L7-L17,L51-L65).

## Global constraints

- Preserve per-session persistent drafts, exact target identity checks and acknowledged-only draft clearing; use Claude's native queue and display (#145).
- Retain customizable Ctrl+Enter to send, Enter for newline and Ctrl+G to hide/show. A competing local keymap must not silently override user customization (#145, #205).
- Keep the adjustable split and on-demand searchable reference browser; inline completion supplements the browser (#145, #202).
- Highlight recognized slash and explicit @file references; show advisory diagnostics for confirmed invalid references without blocking submission (#201).
- Treat unavailable catalogs, permission failures and unfinished tokens separately from confirmed unknown/missing references (#201).
- Current product targets local Windows x64, VS Code 1.128.0+, with automatic composer send requiring Claude 2.1.299+. Ordinary terminal/activity remains at 2.1.287 (#145; package.json:L1-L31; README.md:L98-L107).
- Preserve immutable published v0.11.1 at 3cb45115dae43bd461ddb1281c6ba8d0f7d7bc50 and the stable 0.10.0 channel (#145, #183).
- Use issue-linked commits/PRs in an isolated worktree and the active prerelease route. Do not push the already-merged PR #198 branch (docs/versioning-policy.md:L57-L70; PR #198).
- Proposals and size estimates below are planning judgments; reliable automatic shortcut conflict resolution remains unverified (#204, #205).

## Review focus

1. Very long labels at narrow widths and zoom: favorite controls and full text stay accessible (#199, #203).
2. Catalog/validation responses arrive after a session switch or newer edit: no stale highlighting or suggestions (#201, #202).
3. Paths with spaces, quotes, imported roots, exclusions, symlinks and inaccessible/missing files: correct classification without widening file access (#201).
4. Completion, search/picker inputs, IME and competing shortcuts: no accidental send or doubled action (#202, #204, #205).
5. Explicit user overrides, disabled defaults and chords: local handling preserves customization and terminal behavior (#204, #205).

**Proposed shared interface:** export type ComposerReference = {from: number; to: number; kind: "command" | "file"; value: string; complete: boolean}; export function parseComposerReferences(text: string): readonly ComposerReference[]. Proposed per-editor context: catalog state plus exact session/document/revision identity; editor context changes do not count as draft edits (#201).
