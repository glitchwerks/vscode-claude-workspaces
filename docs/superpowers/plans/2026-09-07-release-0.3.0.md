# Claude Workspaces 0.3.0 Release Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Release the completed 0.3.0 scope as a VS Code Marketplace pre-release, preserve 0.2.0 as the stable channel, and close the completed milestone work with verifiable publication evidence (#64).

**Architecture:** Prepare version, release notes, documentation, and boundary tests on a focused sub-branch of `release-0.3.0`; merge that preparation into the release branch; then merge the accumulated release branch into `main`. An immutable `v0.3.0` tag on the exact merged `main` commit triggers the existing publish workflow, which derives the pre-release channel from the odd minor version, validates/builds/tests/packages the Windows x64 VSIX, publishes it, and creates the GitHub release (`scripts/release-metadata.js:L23-L38`, `.github/workflows/publish.yml:L50-L107`). Publication remains a human approval checkpoint because pushing the tag changes the public Marketplace and GitHub release state (#64).

**Tech Stack:** Node.js 20, npm, TypeScript, Mocha, VS Code extension-host tests, `@vscode/vsce`, GitHub Actions, VS Code Marketplace (`package.json:L35-L45`, `.github/workflows/publish.yml:L45-L94`).

**Spec:** GitHub issue #64

## Release invariants

- Version `0.3.0` must use the Marketplace pre-release channel because odd minor versions are pre-releases; even minor versions remain stable (`README.md:L24-L29`, `scripts/release-metadata.js:L30-L38`).
- The distributable remains a Windows x64 VSIX requiring VS Code 1.120.0 or later (`README.md:L132-L133`, `package.json:L17-L18`).
- This release contains the already-merged scope from #27, #37, #38, #52, #53, #54, and #55. Issue #28/PR #40 and investigation #56 remain outside the release boundary (#64).
- The final release PR body must contain an independent closing directive for every included issue so GitHub closes them when the release branch reaches the default branch (#64).
- The tag must be `v0.3.0`, must not already exist, and must point at the exact release commit on `main`; the release metadata script rejects any tag/package mismatch (`scripts/release-metadata.js:L32-L38`).
- Do not change publishing automation unless validation discovers a release-blocking defect; the current workflow already performs install, typecheck, lint, tests, production build, packaging, checksum creation, Marketplace publication, and GitHub release creation (`.github/workflows/publish.yml:L56-L107`, #64).
