# 0.11.0 Reliability Milestone Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Address the reported typing stalls and terminal corruption, establish reliable activity semantics, and validate a 0.11.0 prerelease against recorded workloads (#180, #56, #158, #183).

**Architecture:** Start with one shared input/output/render/activity baseline. Use that evidence to select small corrections; evaluate native status and notifications alongside the existing mod before choosing authority or delivery ownership. Root-cause fixes remain gated on evidence and a reviewed, specific fix plan, rather than being invented in advance (#183).

**Tech Stack:** TypeScript, VS Code webviews, node-pty 1.1.0, xterm 6.0.0, WebGL addon 0.19.0, Mocha, and the existing Claude completion mod (`package.json:L39-L52,L206-L221`; `media/attention/hooks/register.js:L10-L64`).

**Spec:** `docs/superpowers/specs/2026-10-28-rendering-activity-reliability-investigation-design.md` (PR #184).

- Persist timings, counters, protocol metadata and hashed identities only. Exclude prompts, answers, raw terminal/keyboard contents, free-text OSC messages and paths from captures. Diagnostics must be bounded and default off (`src/attention/attentionDiagnostics.ts:L4-L27,L36-L73`; #158).
- Update README when diagnostics, support requirements or development steps change. Do not fold the deferred features or a complete Windows focus redesign into this release (#183, #176).

## Review Focus

1. Quiet parent with genuine background work: typing remains responsive and activity does not become idle prematurely. Tasks 3–4 and 7 own this matrix (#180, #158).
2. Output bursts plus metadata updates: input order/content survives, queue pressure is visible, and the terminal does not repeatedly detach or lose focus unnoticed. Tasks 3–5 own this regression class (`src/panel/webview/renderer.ts:L282-L312,L654-L658`).
3. Hidden/recreated panels: replay restores the display without generating fresh activity, input waits, capability replies or alerts. Tasks 6–8 own live/replay tests (`src/panel/sessionPanelProvider.ts:L419-L472`; #158).
4. Concurrent agents, cancellation and permission waits: identity, ordering, unread and input-wait state remain coherent. Tasks 7–8 own transition tests (#158).
5. Disabled/expired diagnostics and malformed native input: probes cannot delay/drop user data, grow without bound or leak payloads. Tasks 2–3 and 6 own these tests (#180, #158; privacy model cited above).
