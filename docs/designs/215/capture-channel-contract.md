# Private capture-channel admission and epoch renewal

* **State:** The managed-PTY-exit bridge is selected by the two-Major fix instruction. Ownership, native deny and epoch/data rules remain selected. Not implemented or product-qualified. [Integration authorization; Integration findings]
* **Scope:** The existing private file channel, same subscription-backed CLI, and host-owned capture identity. No HTTP, helper process, Run action or native response broker.
* **Sources:** [R1 findings](reviews/2026-11-07-copying-v1/consolidated_review_report.md#r1--major-define-capture-epoch-admission-and-renewal), [main transaction/budgets](design_draft.md#detailed-implementation), [native mapping](capture-provenance-contract.md). The epoch authority and exchange below are the selected repair rather than claims about existing runtime APIs. [A]

## Authority and identities

The host issues every captureEpoch and offerId as fresh 128-bit lowercase hexadecimal strings. Neither a producer counter nor a native UUID authorizes an epoch. The launch environment continues to carry directory, secret, managed session, canonical CLI UUID and process generation; no changing epoch value is put in the environment. The host's owned control file supplies that value after admission. This keeps the existing launch-field inventory. [A; R1]

Directory and 256-bit secret remain fixed for one managed process generation. Epoch renewal rotates the epoch and offer, not credentials or the CLI. A replacement managed generation gets a new directory/secret and cannot adopt the old channel. Native UUID mismatch retires capture without v1 rebinding; same-UUID resets use the exchange below. Losing the host's in-memory ownership/epoch state fails closed until a matching managed relaunch; do not recover authority from leftover files.

The producer has a module-local cancellation counter solely to cancel obsolete callbacks. It is never serialized as host epoch authority. Only the publisher polls/writes; native observers enqueue or mark reset synchronously and never await this handshake. Matching initial startup notifications are idempotent. A non-startup classic.SessionStart reset cancels the old publisher work and requests renewal once; retransmission of its wire request reuses that request's offer.

## Closed control records

All control records are UTF-8 JSON, at most 4 KiB serialized. Unknown keys, wrong types, nonfinite/unsafe integers, malformed IDs or mismatched binding are rejected. The common envelope is v=1, token (43-character base64url secret), sessionId (1–128 UTF-8 bytes), claudeSessionId (canonical UUID) and generation (1–128 UTF-8 bytes). These are producer/host messages; none reaches the webview or normal logs.

| Record | Required fields beyond common envelope |
|---|---|
| host control | kind=control; controlRevision (positive safe integer); state=offered/granted/active/retired/failed; offerId (hex32 or null); captureEpoch (hex32 or null); grantId (hex32 or null); predecessorEpoch (hex32 or null); reasonCode (closed reason or null); recoveriesRemaining (0 or 1); lastRetired (null or closed captureEpoch/ackSeq/reasonCode object). |
| producer request | kind=epochRequest; offerId (hex32); predecessorEpoch (hex32 or null); nativeSessionId (UUID); reason=initial/native-reset/recover. The offer is the request ID; no producer-created epoch is accepted. |
| producer activation | kind=epochActivate; captureEpoch (hex32); grantId (hex32); nativeSessionId (UUID). |
| host acknowledgement | kind=ack; captureEpoch (hex32); disposition=continue/retired; ackSeq (nonnegative safe integer); reasonCode absent for continue and required for retired. Retain the main design's authenticated envelope and retirement semantics. |

Reasons are SCHEMA_REJECTED, CONTENT_REJECTED, IDENTITY_CHANGED, TRANSACTION_TIMEOUT, CHANNEL_RETIRED, CONTROL_REJECTED or HANDSHAKE_TIMEOUT. Add the last two to the same closed enum in the already-planned capture types/fixtures; no new runtime file is required.

Host control and ack are separate fixed files replaced through host temporary-file rename. The producer writes one request pair named request.<offerId>.upload/.ready and one activation pair named activate.<captureEpoch>.upload/.ready, each exactly once; a marker contains only the basename and declared byte length. The host validates ownership and bounded content before consuming/cleaning these pairs. It never interprets a path supplied inside a record.

There is at most one pending request or activation pair per channel. These control files count toward the existing global storage/file caps. A failed partial producer write is not overwritten or copied repeatedly: the host expires it within the two-second transaction deadline, retires the attempt and cleans only owned files. The five-second handshake deadline still applies. Native continuation is independent of both deadlines. Start the initial five-second handshake clock when the initial offer becomes visible, a renewal clock when a current native-reset request is accepted, and a recovery clock when its offered control becomes visible. An idle standby offer in active state has no handshake deadline. Host retirement first publishes the old retired acknowledgement, then a retired control carrying the replacement offer and lastRetired object; the new grant publishes its epoch-zero acknowledgement before the granted control. Activation publishes active control last, so producer data cannot precede admission.

## State transitions and cursors

| Current host state | Accepted input | Atomic host outcome |
|---|---|---|
| launch prepared | owned directory initialized | offered; captureEpoch/grantId/predecessorEpoch=null; fresh offerId; no ack file yet. |
| offered | initial request with current offer, null predecessor and matching native UUID | consume offer; issue fresh epoch E; granted with grantId=request offer, predecessor=null, offerId=null; publish E/continue/ackSeq=0 before grant visibility. |
| active E | native-reset request with current offer, predecessor=E and matching UUID | retire E at its last admitted ackSeq, invalidate its Copy/review targets and cancel assembly; issue fresh epoch N/ackSeq=0; granted N with predecessor E. |
| retired E | recover request with current offer, predecessor=E and remaining recovery allowance | consume the allowance and offer; issue N/ackSeq=0, granted N; retain E's last admitted cursor only in lastRetired. |
| granted E | activation matching current epoch, grant and native UUID | active E; fresh next offerId; ackSeq remains 0; admit data beginning at seq=1. |
| active E | duplicate activation for E/current grant | return existing active control/ack unchanged; never reset the current cursor. |
| granted/active E | identical duplicate of the request whose offer is current grantId | return the same existing grant/control; do not allocate another epoch or reset seq/ack. |
| any current state | authenticated native UUID mismatch | retire current capture with IDENTITY_CHANGED, invalidate targets, failed with offerId=null; matching managed relaunch required. |
| active/granted E | owned rejection, expired transaction or health/handshake deadline | retire E with unchanged last admitted cursor and visible loss; offer one recovery if eligible, otherwise failed. |
| retired/failed or another epoch | late data/ack/request for an obsolete offer/epoch | do not admit, advance, reopen or retire a newer valid epoch. Host may clean owned obsolete files. |

An initial offered-handshake failure has no admitted data to recover: become failed and require a managed relaunch. After an admitted epoch retires, allow one automatic five-second recovery handshake. If that recovery fails, remain capture-unavailable until matching managed relaunch. A successful admission replenishes the allowance for a later independent retirement; it never causes old observations to be replayed.

Validate the managed-generation envelope/ownership first, then current offer/epoch membership, then native UUID; obsolete offers/epochs are ignored before a mismatching native UUID can affect the current epoch. Heartbeat and partial-transaction/lock deadlines use TRANSACTION_TIMEOUT; initial/activation/recovery handshake expiry uses HANDSHAKE_TIMEOUT. A malformed authenticated request for the current offer consumes/fails that attempt with CONTROL_REJECTED; unauthenticated or foreign traffic cannot consume the offer or retire valid capture. An obsolete valid-token request is stale traffic, not a current owned transaction. Host controlRevision increases on each control replacement and never wraps; revision exhaustion fails closed. The producer ignores lower revisions and stops if the current control contradicts its own pending grant.

After seeing a matching grant, the producer drops old queues, starts a new local source window, sets next data seq=1 and local acknowledged cursor=0, then writes activation. It sends no data until it observes active for that same epoch/grant. Source events lost during renewal produce a visible boundary with unknown extent; they are not joined to either epoch or replayed.

Data filenames include captureEpoch and seq, preventing seq=1 collisions after renewal. Allocate consecutive data sequence values before enqueue. A known dropped queued range is represented by one gap frame at its first sequence with coversThrough equal to its last; accepting it advances ackSeq through that range. An unknown-extent loss consumes one ordinary gap sequence with coversThrough equal to itself and mode=unknown on the selected gap wire member, never a fabricated range. Never bridge source assembly across either gap. Sequence exhaustion retires the epoch instead of wrapping. Every data frame, heartbeat, gap and ack carries its epoch. Heartbeats/gaps use the same consecutive data sequence and acknowledgement path; a reserved gap accounts for any intentionally dropped queued observations before later data is admitted. A retired ack retains the previous cursor; a new epoch's zero is never interpreted as acknowledgement of the old epoch.

### Closed normalized observation dictionary

For storedResult, interpret native string content as one text block. For nested arrays preserve text order and replace unsupported/binary entries with an unavailable placeholder without raw bytes. The 256 KiB reported-output budget applies to the complete retained text surface of that native tool_result block. On overflow send only TOO_LARGE for that output, not a tail; identity/error facts can remain. Do not open persisted/background files. Image guarding may hold native output only within the same queue bounds; if its safety cannot be established, emit MEDIA rather than the original bytes. [C4: output boundaries]

The flags object has exactly interrupted:boolean; backgroundTaskId:nativeId or null; backgroundedByUser/backgroundedByTurnAbort/backgroundedToDeliverMessage:boolean or null; backgroundEndsWithFinalResponse/backgroundWakesOwner:true or null; timedOutAfterMs:finite nonnegative number or null; isImage:boolean or null; backgroundArtifactHint:boolean. A native missing optional field becomes null; a wrong type, empty/overlong task ID or false value for a true-only native hint makes responseState=invalid/flags=null. backgroundArtifactHint records only presence of backgroundOutputPath or backgroundCwdHint; their values are never read into the wire object. Other Bash fields, exitCode, source shell, Run eligibility, arbitrary tool arguments and hidden data are forbidden. Apply the same C4 conflict precedence when call-return and post guards disagree; never select positive execution merely because one observation was positive.

For assistantRow, sum text and command UTF-8 bytes across all retained blocks against the existing 1 MiB assistant-message limit. Each other command is at most 1 MiB. Output text is at most 256 KiB per storedResult. Limit an array to 20,000 elements; additionally cap metadata at 32 KiB, measured as the compact normalized JSON with every text/command string replaced by an empty string. A normalized observation is therefore at most 6×1 MiB+32 KiB = 6,324,224 UTF-8 bytes after JSON escaping. Reject oversized/invalid native content as SOURCE_REJECTED loss without partial Copy; a valid typed invalid guard is not a transport rejection. These selected bounds refine the existing finite-budget requirement; they are not measured throughput or new SDK APIs. [A2; main budgets]

Malformed JSON, unknown keys/kinds, wrong types/member combinations and observation/chunk ordering violations retire an authenticated current epoch with SCHEMA_REJECTED. Declared-versus-actual byte mismatch, aggregate content/retention failure or a valid-shaped but unusable source constraint uses CONTENT_REJECTED. Assembly/file expiry uses TRANSACTION_TIMEOUT. Foreign/stale managed bindings never retire valid capture; a native UUID mismatch is reported through epochRequest.nativeSessionId and retains the selected IDENTITY_CHANGED control policy.

### Native call-return branch selection

The pinned ToolCallResult deny variant is a **string**, including the empty string; it is not a permission boolean. Read only own declared native fields from the same observed tool.call closure. Treat absent or own undefined deny as absent (the other union members declare deny?:undefined). A defined own deny of any other type, including null/boolean/number, normalizes to branch=unknown, flags=null without falling through to isError or result. A string deny is valid only when the deny variant's other declared fields result/context/ref/text/isError/isReadOnly are all absent or undefined; a populated contradictory field also yields unknown/null. For a valid deny emit only kind/scope/toolUseId/branch/flags, never the reason string. Unknown native metadata is not forwarded. [Native declaration](evidence/c4-native-evidence.md#toolcallresult); [Current auto accept; Current review:F1].

With deny absent/undefined, r.isError===true selects error/null. Otherwise a fully validated declared Bash result and flags selects bash; anything else selects unknown/null. Neither unknown nor error/deny supplies positive execution evidence. A malformed native envelope remains a typed source guard, distinct from malformed normalized wire data (which retires the epoch). A valid string deny records withholding, not PermissionDenied: C4-08 stays Unknown / Execution not confirmed with requested Copy only; a later string deny in C4-26 does not undo its independent positive post/stored-result pair. Keep the original native case bodies. ### Serialization, revision and completion

The producer allocates observationId consecutively from 1 for each admitted epoch. Serialize only the chosen normalized object, in compact JSON with scalar-preserving JSON string escaping and no added whitespace; property order need not be canonical. Calculate UTF-8 byte total/count and emit chunks from that same immutable object. Construct fresh normalized objects/arrays from the selected primitive values and enqueue an immutable snapshot; never retain a mutable SDK row/response as the queued record. Do not stringify the original native object. Use a bounded counting pass followed by bounded emission in the publisher, so escaped multi-megabyte JSON need not coexist as an unbounded second queued string. JSON.stringify on bounded string pieces is sufficient; no producer hashing/crypto or undeclared fs API is required. All pending source/metadata and prepared frame bytes count toward the existing 4 MiB/64-slot producer queue; an unencoded observation consumes a slot too. It has no frame seq yet: dropping it emits an unknown gap. Allocate seq before enqueuing each prepared frame; a loss of allocated queued frames can use a known range. Staged files keep their existing separate 2 MiB/eight-transaction cap.

Publish one observation's chunks in order; heartbeat may interleave, another observation may not. The first index is 0; every later chunk repeats its observationId/count/total exactly. Exact total bytes and all consecutive indices are required, including for an empty text value (its enclosing JSON is still nonempty). No explicit commit frame is needed: the final required chunk is the commit boundary only after complete JSON, schema, source-key and budget validation. There is no Copy, visible partial source or positive provenance from incomplete chunks. A frame with seq≤ackSeq is stale and cannot re-admit content; a repeated chunk at a new seq or a second first chunk while an assembly is open is a schema rejection, not a retry. Semantic duplicate native observations at different observationIds use C4's existing idempotence/conflict policy.

Reserve one bounded assembly per channel in the existing source/derived-text retention accounting. Before starting, reserve totalByteLength plus the 1 MiB+32 KiB maximum decoded observation, evicting complete old groups if needed; do not exceed session/global budgets. Release serialized assembly text after decoding before allocating render-derived text. Every valid consecutive frame can advance the transport ack while an observation is incomplete, but only complete validated observations mutate the source model. On malformed final payload, retire with last previously admitted seq, discard the whole assembly and invalidate its incomplete source; earlier chunk acks never mean Copy was ready.

Gap admission discards any open assembly, exposes loss and resets observation continuity; after a gap accept a fresh index-0 observation with a greater observationId, never resume the old observation. Known gaps advance ack through coversThrough; unknown gaps advance only their own seq. A new epoch resets observationId and seq; no observation or native key is joined across a gap/epoch. Without a gap, a changed observationId must be exactly the last completed ID+1. Exhausted counters retire instead of wrapping.

The two-second transaction deadline remains per staged upload/marker/lock operation. Add a selected 30-second absolute observation-assembly deadline, with a five-second no-chunk-progress deadline; heartbeat does not extend either. On expiry retire with TRANSACTION_TIMEOUT and discard the incomplete record. Keep native continuation and Raw/Escape independent. These are finite design budgets for later qualification, not measured latency. The serialized vectors cover each outer member and all normalized kinds, non-ASCII/newline quoting, multi-chunk commit, source guards, malformed/extra/private fields, order/length mismatch, gap abandonment and expiry. [A2; F]
