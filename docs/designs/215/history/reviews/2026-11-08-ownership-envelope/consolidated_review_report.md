## R1 — Major — Select the exit-confirmation bridge for current-owner cleanup

**Affected scope:** main inventory/P3 integration and ownership instructions; CH L34–L42; O18/O19/O27; planned capture/runtime and extension composition. [Main integration](https://github.com/glitchwerks/vscode-claude-workspaces/blob/eb11873050cbcc09ece0ea3c32de1f4d39c4a345/docs/designs/215/design_draft.md#L188-L259), [CH cleanup authority](https://github.com/glitchwerks/vscode-claude-workspaces/blob/eb11873050cbcc09ece0ea3c32de1f4d39c4a345/docs/designs/215/capture-channel-contract.md#L34-L42).

The selected current-owner cleanup branch requires a confirmed PTY process exit for the frozen managed generation. SessionManager privately subscribes to ManagedPty.onExit but exposes session/data events, with no public confirmed-exit receipt. Record removal also occurs on startup/failure/disposal paths; closing, disappearance, native session.end or a settled terminate promise cannot stand in for that receipt. The current target lookup loses authority as a session closes/disappears. The plan selects no bridge into capture cleanup and no corresponding API/allowlist change. O18's supplied managedProcessExitConfirmed boolean therefore leaves a production integration decision unresolved. [Public surface](https://github.com/glitchwerks/vscode-claude-workspaces/blob/ef5fd48f4b676881a8730afbf8e583e70565ca11/src/sessions/sessionManager.ts#L59-L87), [private registration](https://github.com/glitchwerks/vscode-claude-workspaces/blob/ef5fd48f4b676881a8730afbf8e583e70565ca11/src/sessions/sessionManager.ts#L143-L213), [exit/removal paths](https://github.com/glitchwerks/vscode-claude-workspaces/blob/ef5fd48f4b676881a8730afbf8e583e70565ca11/src/sessions/sessionManager.ts#L458-L525), [target lifetime](https://github.com/glitchwerks/vscode-claude-workspaces/blob/ef5fd48f4b676881a8730afbf8e583e70565ca11/src/composer/composerRuntime.ts#L70-L92), [O18/O19](https://github.com/glitchwerks/vscode-claude-workspaces/blob/eb11873050cbcc09ece0ea3c32de1f4d39c4a345/docs/designs/215/evidence/capture-channel-cases.json#L2983-L3090).

**Required design correction:** select the exact exit-proof producer/bridge, callback signature, session/native UUID/generation correlation, listener lifetime, startup/abandonment handling and shutdown ordering. Reconcile source/test write paths if the choice changes them. Preserve conservative retention when exit is uncertain. Add end-to-end fake-PTY integration expectations: a real exit permits O18 only for the frozen owner; terminate-without-exit, native transition, startup removal and obsolete-generation exit do not. An existing lifecycle logger callback and lower-level factory/event are possible inputs, but the current plan does not select one as authority. [Lower-level event](https://github.com/glitchwerks/vscode-claude-workspaces/blob/ef5fd48f4b676881a8730afbf8e583e70565ca11/src/launch/managedPty.ts#L5-L17), [fake terminate versus emitExit](https://github.com/glitchwerks/vscode-claude-workspaces/blob/ef5fd48f4b676881a8730afbf8e583e70565ca11/test/support/fakeManagedPty.ts#L34-L79), [existing logger interface](https://github.com/glitchwerks/vscode-claude-workspaces/blob/ef5fd48f4b676881a8730afbf8e583e70565ca11/src/sessions/sessionTypes.ts#L56-L66), [full independent rationales](implementation_readiness_report.md).

## R2 — Major — Specify the host-issued viewId bootstrap

**Affected scope:** planned provider/browser/renderer/protocol integration; VW L7–L11 and L59–L62; P01/P02 and V05. [Host-issued identity requirement](https://github.com/glitchwerks/vscode-claude-workspaces/blob/eb11873050cbcc09ece0ea3c32de1f4d39c4a345/docs/designs/215/companion-view-contract.md#L7-L11), [first ready/bind payloads](https://github.com/glitchwerks/vscode-claude-workspaces/blob/eb11873050cbcc09ece0ea3c32de1f4d39c4a345/docs/designs/215/companion-view-contract.md#L59-L62).

VW says the host creates a hex32 viewId for each renderer document and supplies it through an existing trusted bootstrap. The pinned browser entry instead creates its legacy documentId locally with crypto.randomUUID(); the provider HTML contains no host identity bootstrap and learns the legacy ID from ready. The first companion.ready already requires viewId, while companion.bind also requires it. The selected root wrapper preserves type discrimination but supplies no initial identity transfer. P01/P02 begin with prefilled IDs and do not establish the startup path. [Browser-generated legacy ID](https://github.com/glitchwerks/vscode-claude-workspaces/blob/ef5fd48f4b676881a8730afbf8e583e70565ca11/src/panel/webview/index.ts#L19-L40), [actual provider HTML](https://github.com/glitchwerks/vscode-claude-workspaces/blob/ef5fd48f4b676881a8730afbf8e583e70565ca11/src/panel/sessionPanelProvider.ts#L359-L398), [legacy ready registration](https://github.com/glitchwerks/vscode-claude-workspaces/blob/ef5fd48f4b676881a8730afbf8e583e70565ca11/src/panel/sessionPanelProvider.ts#L615-L647), [prefilled root examples](https://github.com/glitchwerks/vscode-claude-workspaces/blob/eb11873050cbcc09ece0ea3c32de1f4d39c4a345/docs/designs/215/evidence/companion-view-cases.json#L1124-L1164).

**Required design correction:** select the exact bootstrap carrier/fields and host allocation, browser read/validation, renderer dependency and provider binding checks. Define missing/malformed-bootstrap fallback, rotation/revocation on document recreation/disposal, and compatibility with the legacy documentId path. Reconcile dictionary/allowlists where needed. Add provider→initialization→browser→companion.ready integration expectations, including a stale document's well-shaped ready after recreation and a renderer without bootstrap. Do not accept a view-supplied arbitrary ID as host authority. [Current root/view integration](https://github.com/glitchwerks/vscode-claude-workspaces/blob/eb11873050cbcc09ece0ea3c32de1f4d39c4a345/docs/designs/215/design_draft.md#L289-L291), [renderer dependency](https://github.com/glitchwerks/vscode-claude-workspaces/blob/ef5fd48f4b676881a8730afbf8e583e70565ca11/src/panel/webview/renderer.ts#L54-L70), [complete finding](implementation_readiness_report.md).

The missing existing bootstrap and unselected startup mechanism are source/document facts. Failed admission or stale-document acceptance are conditional implementation consequences; neither was observed in a running renderer. [Evidence classification](implementation_readiness_report.md).
