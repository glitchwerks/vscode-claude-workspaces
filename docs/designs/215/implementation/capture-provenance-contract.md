## Source and identity rules

Reuse the host target tuple (sessionId, claudeSessionId, generation) from the existing read-only target API and add the owning captureEpoch. Native events cannot replace those values. The native session ID observed by lifecycle/classic hooks must agree with that binding; an authenticated reset mismatch follows the approved capture-retirement policy. Host generation is a string identity, not a turn counter. [Pinned target API](https://github.com/glitchwerks/vscode-claude-workspaces/blob/ef5fd48f4b676881a8730afbf8e583e70565ca11/src/composer/composerRuntime.ts#L69-L74).

Agent scope is a tagged main value when agentId/agent_id is absent, or a tagged agent value carrying that exact ID. Never use agent_type, tool name, command text, a result ref or temporal proximity as the correlation key. The tool key is (host target, captureEpoch, agent scope, tool_use_id); the row key substitutes stored row uuid and block index. Native IDs must be nonempty strings bounded to 256 UTF-8 bytes; do not invent IDs when absent. [Evidence: AgentLoop and classic base fields](evidence/c4-native-evidence.md#agentloop), [origin](evidence/c4-native-evidence.md#origin) (`docs/designs/215/evidence/c4-native-evidence.md:L18-L57`).

This initial adapter projects the main conversation. Non-main observations cannot be joined into main or acquire a main executed label; their content is unqualified and omitted rather than exposing worker/internal-loop material. Keep a bounded metadata-only unsupported-scope indication. The main explanation, including its native agent summaries, remains intact. This is a v1 qualification boundary, not a claim that subagent capture is impossible. [Declared scope fields](evidence/c4-native-evidence.md#basehookinput); [prior experiment limits](https://github.com/glitchwerks/vscode-claude-workspaces/issues/215#issuecomment-6647462596).

## Exact native observation table

Every observer calls next with the unchanged input once, relays its exact return or original rejection, and enqueues only bounded allowlisted data without awaiting file delivery. Capture overflow records a gap and cannot decide permissions or delay native continuation. Input fields may be snapshotted for identity before next; stored-row content is read only from the returned row. [Continuation/evidence semantics](evidence/c4-native-evidence.md#declaration-semantics-used-by-the-mapping) (`docs/designs/215/evidence/c4-native-evidence.md:L291-L301`).

| Event | Exact fields used | Admission and normalized meaning |
|---|---|---|
| session.start | $.session.id(), $.session.version(); native e.cwd/isInteractive are not command content | Establish build/CLI identity against the managed binding. Do not infer subscription auth or alter it. Observe the unchanged native result; no content is manufactured. |
| classic.SessionStart | e.session_id, e.source, e.agent_id | Main lifecycle observation. Matching initial startup is idempotent; same-UUID clear/resume/compact/fork begins a fresh epoch/boundary. UUID mismatch pauses capture until a new matching managed launch. Never rebind from the event. |
| session.end | e.sessionId, e.reason | Retire that capture identity and invalidate its actions; no background-output read or model query. This build describes clear/resume as session transitions that may keep the process alive; do not replace the process-owned Run shell merely because capture retires. |
| session.append, assistant response | e.door=response, e.origin.kind=model, e.agentId; returned r.uuid and r.message.{type,role,content}; original e.uuid for equality check | Require r.uuid=e.uuid, no deny, assistant type/role and main scope. Capture each returned content[i] where type=text and text is string, preserving exact text and original i. Use r, never r.message ?? e.message. Thinking is excluded; unsupported public media gets a non-copyable placeholder. |
| session.append, model Bash request | The same stored assistant row; content[i].{type=tool_use,id,name=Bash,input.command} | Keep the literal displayed command as a Requested target, associated with row UUID/block index and the same tool-call key. This is not execution evidence. Never classify arbitrary tool arguments as commands. |
| tool.call entry | next.origin.{plugin,tier}, e.tool, e.tool_use_id, e.agentId, e.command | Bind a real Bash request when origin is engine/core and it matches the main model request. A plugin-origin call is not a Claude model request. Keep the observed request value separately if it differs; it is not automatically the executed value. |
| tool.call return | From the same closure: r.deny; r.isError; whether r.result is the declared Bash record; r.ref presence | Record answered/error/deny/unknown branch. No branch alone proves what ran. ref is not a correlation ID; deny may occur after execution, and error can represent refusal, validation failure or interruption. Do not forward context or raw text/result from this envelope as public output. |
| classic.PostToolUse for Bash | e.session_id, e.agent_id, e.tool_name, e.tool_use_id, e.tool_input.command; validated e.tool_response flags below | Native post evidence supplies the effective command, which may differ from the model request. Do not take executed text from the earlier request. Await the matching retained non-error tool_result before a completed/backgrounded executed target is ready. |
| classic.PostToolUseFailure for Bash | Same identity/tool/input fields; e.is_interrupt when boolean | Record a tool failure or explicit interruption report. Do not parse e.error for execution, exit code or finality, and do not forward pre-storage error content. is_interrupt=false/absent is not proof that nothing was interrupted. |
| classic.PermissionDenied for Bash | e.session_id, e.agent_id, e.tool_name, e.tool_use_id, e.tool_input.command | Report Permission denied for this key, with execution unconfirmed. Do not serialize reason/rules. A conflict with positive post evidence becomes Unknown rather than choosing a story. |
| session.append, stored Bash result | e.door=tool-result, e.origin.kind=tool and tool=Bash, e.agentId; returned stored user row; content[i].{type=tool_result,tool_use_id,is_error,content} | Match the existing Bash request/key. This is the only reported-output text source. Accept string content or ordered text blocks; ignore binary/unknown nested blocks with a placeholder. Preserve exact text, but never extract executable commands from tool output. Explicit is_error=false is required for positive completion; true is error; absent/invalid is unknown. |

Declaration shapes and original line coordinates: [append](evidence/c4-native-evidence.md#sessionappendinput), [tool-call envelope](evidence/c4-native-evidence.md#toolcallresult), [classic post/failure/denial](evidence/c4-native-evidence.md#posttoolusehookinput), [lifecycle](evidence/c4-native-evidence.md#sessionstarthookinput) (`docs/designs/215/evidence/c4-native-evidence.md:L58-L241`). The classic post fields are declared for this build; not every row above has a preserved live receipt.

Do not register a C4 tool.check or PermissionRequest response handler. PermissionRequest has no tool_use_id in this build, and a check/query does not execute a tool. Never match permission data by command equality, including apparently unique identical-command cases. Existing native attention and Variant A own input. classic.PreToolUse uses flattened e.tool/e.command/e.tool_use_id rather than settings-style tool_name/tool_input, but is not needed as another C4 authority source. turn.complete, turn.abort acknowledgements, prompt text and terminal rows never supply a tool outcome. [Permission declaration](evidence/c4-native-evidence.md#permissionrequesthookinput), [native semantics](evidence/c4-native-evidence.md#declaration-semantics-used-by-the-mapping).

## Bash result flags and data boundaries

Read these only after validating the declared Bash result shape: interrupted:boolean; optional backgroundTaskId:string; backgroundedByUser/backgroundedByTurnAbort/backgroundedToDeliverMessage booleans; backgroundEndsWithFinalResponse/backgroundWakesOwner true-only hints; timedOutAfterMs:number; and isImage:boolean for output suppression. A background flag or timeout is a reason hint, never proof of termination. Presence of the excluded backgroundOutputPath/backgroundCwdHint fields may only yield a boolean background-artifact hint, never their values; a hint without a task ID also blocks foreground completion. Nonempty backgroundTaskId plus non-interrupted positive post evidence supports Backgrounded (last reported). A hint without the task ID, or simultaneous interrupted/backgrounded claims, produces Unknown. [Complete Bash member index](evidence/c4-native-evidence.md#builtintoolresults-bash-member-index) (`docs/designs/215/evidence/c4-native-evidence.md:L254-L290`).

The declared Bash record has no numeric exit-code member. This adapter always uses exitCode=null; neither stderr, isError, returnCodeInterpretation nor prose such as Exit code 7 is a numeric exit-code channel. Tool completed reports native tool completion, not exit zero or success of every process in a script. A nonzero-looking error without independent execution evidence remains Tool reported error; execution not confirmed. No new live probe is required to specify that conservative outcome. [Member index](evidence/c4-native-evidence.md#builtintoolresults-bash-member-index), [exact receipt variants](evidence/c4-native-evidence.md#selected-exact-receipt-fields).

Generated fields marked internal are used only as pinned-build negative/finality guards, not as cross-version guarantees or new control APIs. Unknown builds remain outside this adapter.

Do not forward stdout/stderr from pre-storage classic/tool-call records. The retained tool_result content is the output surface, so canonical text rewrites remain visible. Exclude context arrays, structuredContent, raw/persisted/background/tail paths, hidden metadata and thinking. Never open output files or transcript paths to backfill. isImage=true suppresses binary-looking output in favor of an unavailable-media placeholder. Apply the existing 256 KiB reported-output budget; full command targets keep their separate literal-value limits. Logs remain content-free. No Run/path extraction is performed on tool-output prose.

## State, finality and Copy/Run-again evidence

A positive completed target requires all of: a stored main model Bash request; its engine/core tool.call binding; a matching valid native PostToolUse with the effective command; and a retained matching tool_result with is_error=false. Conflicting evidence makes the state Unknown and invalidates any previous executed action revision. Pending and stored observations may arrive in either order; assemble by identity within the existing finite model budgets, never by text. [Source shapes](evidence/c4-native-evidence.md#toolcallinput), [post input](evidence/c4-native-evidence.md#posttoolusehookinput), [source receipts](evidence/c4-native-evidence.md#selected-exact-receipt-fields).

| Evidence at the key | Visible state | Executed target / evidence-only Run again |
|---|---|---|
| Stored request, no positive post/stored-result pair | Requested by Claude; execution not confirmed | Requested command Copy only; no executed target. |
| Full positive pair, interrupted=false, no background ID or hint | Claude ran this / Tool completed; exit code unavailable | Copy the exact post-tool effective command. Run-again evidence is eligible with declared source family bash. |
| Full positive pair with background task ID and no interruption conflict | Claude started this / Backgrounded (last reported) | Exact effective Copy; no Run again because final completion is not established. |
| Native PermissionDenied, no positive conflict | Permission denied; execution not confirmed | Preserve requested Copy only. |
| Error return or PostToolUseFailure without positive execution evidence | Tool reported error; execution not confirmed | Preserve requested Copy; no numeric Failed/Ran claim. |
| Native is_interrupt=true or Bash interrupted=true without the completed positive pair | Interruption reported; execution not confirmed | No complete/terminated claim or Run again. |
| is_interrupt=false plus aborted turn | Keep the supported error/unknown state | Never manufacture interruption confirmation. |
| Deny without positive native evidence | Execution not confirmed | Not necessarily denied before execution. |
| Deny after an already complete positive pair | Keep the supported completed state | A later withholding cannot undo native execution. |
| Conflicting native denial/post, different effective values at one ID, malformed background evidence | Unknown / conflicting native evidence | Invalidate executed actions; retain literal requested source. |
| Completion notification, task-output text or another Bash reading a background file | No promotion of the original task | These have no supported structured completion mapping in this adapter. |
| Native reset, source gap, stale epoch/generation or evicted source | Unavailable/unknown under existing lifecycle policy | Stale Copy/review/Run targets are rejected; never retarget. |

No native event proves live OS-process termination for every case. A background status is explicitly last reported. The adapter does not introduce TaskOutput/TaskStop, PowerShell, MCP or arbitrary tool-result adapters; generic unsupported results are not mislabeled as Bash execution. User-launched Run outcomes remain on the separate VS Code terminal service and do not alter Claude provenance.

Run-again evidence eligibility is not execution permission. It still requires the approved source/shell matrix, current immutable source/revision, host target, qualified owned profile/build, readiness checks and C2 closure. Source family bash comes from this adapter's explicitly declared built-in Bash provider, not a classifier over command text; it does not establish portability to pwsh or another profile. [Existing Run contract](https://github.com/glitchwerks/vscode-claude-workspaces/blob/a9818b4e811bae0cb833914ad90c4ce49243e100/docs/designs/215/run-amendment.md#run-eligibility-matrix).

## Revisions and replay

Keep displayed and effective command values as separate immutable source-backed targets when the post input differs. Duplicate identical evidence is idempotent and must not create a second target. A conflicting observation at the same key invalidates prior executed target revisions instead of overwriting evidence silently. Different IDs with the same command remain distinct. Scope/epoch/host binding changes cannot merge records, and known gaps cannot be bridged to invent completion.

On returned append UUID mismatch, missing/denied stored message or invalid field type, emit no guessed source target. Unknown public blocks may render a placeholder; private/internal blocks are excluded. Record a bounded unavailable/gap indication under the existing capture policy. Do not confuse native-source validation with accepting a malformed transport frame; authenticated bad transport still uses the approved retired acknowledgement policy.

## Native withholding transfer

The declared tool.call return deny member is a string, including empty, not a boolean permission result. CH selects exact absent/undefined/invalid/mixed-field normalization and excludes its reason from serialized data. nativeDenyPipelines transfer the unchanged C4-08/C4-26 bodies through normalized wire to model/VW: withholding alone stays execution-unconfirmed, while withholding after a complete positive pair preserves completion. These are synthetic design expectations, not new native observations.
